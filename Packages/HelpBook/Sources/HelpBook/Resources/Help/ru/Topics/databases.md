# Онлайновые каталоги

> Три публичных каталога, дающие имена идентификаторам, найденным в дампе. Без них программа работает.

Часть того, что показывают инструментальные модули, в файле не содержится: это имя, данное сообществом идентификатору, который в файле есть. За такими именами ByteRipper обращается по HTTPS в три публичных каталога и хранит полученное сутки:

- **Имена GUID UEFI** — из проекта UEFITool. Именно благодаря им [[topic:tool-uefi|инструмент UEFI]] показывает вместо голого [[term:guid|GUID]] «AmiBoardInfo» или «DxeCore».
- **Микрокод процессоров** — из коллекции CPUMicrocodes. По ней именуются обновления микрокода, которые перечисляет [[topic:tool-fit|инструмент FIT]]: сигнатура процессора, ревизия и дата. Из неё же берётся список для команды **Добавить микрокод…**.
- **База прошивок ME** — из проекта ME Analyzer. Благодаря ей [[topic:tool-me|инструмент ME]] может сказать, какому известному релизу соответствует образ.

## Где измерение, а где имя

Инструменты последовательно разделяют эти две вещи:

- **Байты принадлежат файлу.** Адрес, размер, поле версии, контрольная сумма прочитаны из самого образа.
- **Имя принадлежит каталогу.** Это опознание, сделанное сообществом: его может не быть, и оно может быть неверным.

Поэтому строка «AmiBoardInfo · 0x7A0000 · 0x12C0» означает, что в файле по этому адресу действительно есть модуль такого размера, а каталог относит этот GUID к числу тех, которые принято называть AmiBoardInfo.

## Без сети

Ни одна функция программы не требует сети. Без подключения или при заблокированном запросе инструменты показывают идентификаторы вместо имён и ничего больше об этом не сообщают: ни диалогов, ни повторных попыток. Всё, что прочитано из байтов, при этом не меняется.

Ничто об открытом файле никуда не передаётся: это чтение публичных списков, и дамп машину не покидает.

Кроме того, раз в сутки программа проверяет, не вышла ли её новая версия. Это четвёртое и последнее обращение к сети.
