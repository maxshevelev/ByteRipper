# Разборы кода и сервер разборов

> Разбор кода — это то, что Ghidra нашла в одном модуле PEI или DXE: функции, инструкции, декомпилированный код на C и имена, которые им дал разбор. ByteRipper читает разборы из хранилища — из папки на этом Mac или с сервера разборов, общего для всех Mac в сети.

Разбор создаёт скилл Ghidra вне ByteRipper. ByteRipper читает то, что скилл сохранил: модуль дерева UEFI, для которого есть разбор, отмечен значком кода, а команда **Открыть с кодом** показывает его код рядом с байтами; панель описана на странице [[topic:code-panel|Панель кода]]. Пока файл модуля свёрнут, значок стоит после имени файла, поэтому по списку свёрнутых файлов видно, для каких модулей есть разбор; при разворачивании файла значок переходит на секцию с модулем. Разбор привязан к байтам модуля, а не к дампу, поэтому тот же модуль в другом дампе открывает тот же разбор.

## Где хранятся разборы

Хранилище выбирается в **Настройки ▸ Разбор кода**.

- **На этом Mac** — разборы читаются из собственной папки этого Mac, `~/Library/Application Support/ByteRipper/Analysis`. Туда же пишет скилл Ghidra, когда работает на этом Mac. Это настройка для одного компьютера.
- **На сервере разборов** — разборы читаются с `byteripper-server`, программы, работающей на одной из машин сети. Все Mac, в которых указан один и тот же сервер, видят одни и те же разборы: модуль, разобранный один раз, доступен на каждом из них.

Настройка определяет только, откуда читаются разборы. При её смене ничего не копируется и не удаляется: папка на этом Mac остаётся как есть, и при возврате к варианту **На этом Mac** её разборы снова видны.

## Подключение к серверу

Сервер настраивается один раз, в Терминале той машины, на которой он работает:

1. `byteripper-server token add --name admin --rights admin` создаёт admin-токен сервера и выводит его один раз. Сервер хранит только хэш этого токена, и без него не запускается.
2. `byteripper-server token add --name <имя-mac> --preset app` создаёт токен для одного Mac: свой токен нужен каждому Mac и каждому скрипту, который читает сервер. Секрет выводится один раз и больше нигде не хранится.
3. `byteripper-server --listen 127.0.0.1:8765 --listen 100.64.0.7:8765` запускает сервер на указанных адресах: адрес обратной петли — для ByteRipper на самой машине сервера (Mac не может подключиться к собственному адресу в частной сети, например Tailscale), адрес в частной сети — для остальных Mac.

Токен требуется на каждом адресе, который слушает сервер, включая адрес обратной петли. Обычно указывается адрес сервера в частной сети, например Tailscale; такая сеть к тому же шифрует соединение.

На каждом Mac в **Настройки ▸ Разбор кода**:

1. Выберите **На сервере разборов**.
2. Введите адрес в виде `http://host:port` (на самой машине сервера — `http://localhost:8765`) и токен, который сервер вывел для этого Mac.
3. Нажмите **Подключить**.

Строка под полями сообщает, доступен ли сервер. Если сервер не принимает токен или на этом Mac токена нет, строка сообщает именно об этом, а не о недоступном сервере; при отказе она называет права, которых в токене нет. Токен хранится в файле, который может читать только текущий пользователь, — `~/Library/Application Support/ByteRipper/Server/token`. Если поле токена оставить пустым, используется уже сохранённый токен.

## Работа с сервером

- **Новые разборы появляются сами.** Сервер сообщает о каждом изменении сразу, поэтому разбор, сохранённый или опубликованный с любой машины, через секунду-другую появляется на всех Mac, а открытая панель кода перерисовывается из него на том же месте.
- **Прочитанное остаётся доступным.** Этот Mac хранит копию того, что он уже прочитал с сервера. Если сервер недоступен, строка в настройках сообщает об этом; уже прочитанные разборы по-прежнему показываются, ещё не прочитанные — нет. Подключение повторяется автоматически.
- **Проекты работают с сервером.** При открытии проекта разборы, которые он хранит, отправляются на сервер, и сервер принимает их по обычным правилам (см. [[topic:projects|Проекты]]); уведомление после открытия передаёт ответ сервера.

## Разбор силами агента

Если на сервере разборов работает и Ghidra, агент, подключённый к ByteRipper (см. [[topic:agent|Работа с агентом]]), может разбирать модули на сервере: открыть модуль по узлу образа PE32 или TE в дереве UEFI, дать имена функциям, переменным и типам, написать комментарии и опубликовать результат. Каждая публикация — новая ревизия разбора модуля; её показывают все Mac, которые читают этот сервер. Проект Ghidra остаётся на сервере, поэтому разбор можно продолжить позже — агенту или пользователю. Агент, работающий на самом сервере, подключается к `byteripper-server` напрямую, по адресу `/mcp`.

## Отправка разборов этого Mac

Кнопка **Отправить разборы этого Mac на сервер** копирует на сервер все разборы из папки этого Mac. Она нужна при первом подключении, когда на этом Mac есть разборы, которых нет на сервере. Сервер принимает каждый разбор по тем же правилам, что и разборы проекта: более поздняя ревизия заменяет более раннюю, разбор модуля из другого проекта откладывается отдельно и не заменяет имеющийся, а разбор, который уже есть на сервере, остаётся без изменений. Строка под кнопкой показывает, сколько разборов принято в каждом из этих случаев. Для отправки нужно право `cas.write`; токен без него сервер не принимает, и строка указывает, какого права не хватает.

## Чего сервер не делает

- Сервер рассчитан на сеть одного пользователя: у каждого клиента свой токен, а права в нём определяют, что этому клиенту разрешено, — токен `reader` только читает, токен `app` ещё и записывает и публикует. Собственной модели пользователей у сервера нет.
- Сервер ничего не удаляет по сети. Ненужные разборы удаляются на самом сервере командой `byteripper-cas gc`.
- Сервер не хранит дампы. Разбор указывает, какой модуль он описывает, но не содержит прошивку, из которой этот модуль взят.
