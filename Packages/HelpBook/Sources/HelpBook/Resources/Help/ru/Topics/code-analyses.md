# Разборы кода и сервер разборов

> Разбор кода — это то, что Ghidra нашла в одном модуле PEI или DXE: функции, инструкции, декомпилированный код на C и имена, которые им дал разбор. ByteRipper читает разборы из хранилища — из папки на этом Mac или с сервера разборов, общего для всех Mac в сети.

Разбор создаёт скилл Ghidra вне ByteRipper. ByteRipper читает то, что скилл сохранил: модуль дерева UEFI, для которого есть разбор, отмечен значком кода, а команда **Открыть с кодом** показывает его код рядом с байтами. Разбор привязан к байтам модуля, а не к дампу, поэтому тот же модуль в другом дампе открывает тот же разбор.

## Где хранятся разборы

Хранилище выбирается в **Настройки ▸ Разбор кода**.

- **На этом Mac** — разборы читаются из собственной папки этого Mac, `~/Library/Application Support/ByteRipper/Analysis`. Туда же пишет скилл Ghidra, когда работает на этом Mac. Это настройка для одного компьютера.
- **На сервере разборов** — разборы читаются с `byteripper-server`, программы, работающей на одной из машин сети. Все Mac, в которых указан один и тот же сервер, видят одни и те же разборы: модуль, разобранный один раз, доступен на каждом из них.

Настройка определяет только, откуда читаются разборы. При её смене ничего не копируется и не удаляется: папка на этом Mac остаётся как есть, и при возврате к варианту **На этом Mac** её разборы снова видны.

## Подключение к серверу

Сервер настраивается один раз, в Терминале той машины, на которой он работает:

1. `byteripper-server token` создаёт токен и выводит его.
2. `byteripper-server --listen 100.64.0.7:8765` запускает сервер на указанном адресе.

На любом адресе, кроме адреса обратной петли самой машины, сервер без токена не запускается. Обычно указывается адрес сервера в частной сети, например Tailscale; такая сеть к тому же шифрует соединение.

На каждом Mac в **Настройки ▸ Разбор кода**:

1. Выберите **На сервере разборов**.
2. Введите адрес в виде `http://host:port` и токен, который вывел сервер.
3. Нажмите **Подключить**.

Строка под полями сообщает, доступен ли сервер. Токен хранится в файле, который может читать только текущий пользователь, — `~/Library/Application Support/ByteRipper/Server/token`; этот же файл читают скрипты скилла Ghidra на этом Mac. Если поле токена оставить пустым, используется уже сохранённый токен.

## Работа с сервером

- **Новые разборы появляются сами.** Сервер сообщает о каждом изменении сразу, поэтому разбор, сохранённый или опубликованный с любой машины, через секунду-другую появляется на всех Mac, а открытая панель кода перерисовывается из него на том же месте.
- **Прочитанное остаётся доступным.** Этот Mac хранит копию того, что он уже прочитал с сервера. Если сервер недоступен, строка в настройках сообщает об этом; уже прочитанные разборы по-прежнему показываются, ещё не прочитанные — нет. Подключение повторяется автоматически.
- **Проекты работают с сервером.** При открытии проекта разборы, которые он хранит, отправляются на сервер, и сервер принимает их по обычным правилам (см. [[topic:projects|Проекты]]); уведомление после открытия передаёт ответ сервера.

## Отправка разборов этого Mac

Кнопка **Отправить разборы этого Mac на сервер** копирует на сервер все разборы из папки этого Mac. Она нужна при первом подключении, когда на этом Mac есть разборы, которых нет на сервере. Сервер принимает каждый разбор по тем же правилам, что и разборы проекта: более поздняя ревизия заменяет более раннюю, разбор модуля из другого проекта откладывается отдельно и не заменяет имеющийся, а разбор, который уже есть на сервере, остаётся без изменений. Строка под кнопкой показывает, сколько разборов принято в каждом из этих случаев.

## Чего сервер не делает

- Сервер рассчитан на сеть одного пользователя: токен один, и тот, у кого он есть, может читать и записывать все разборы.
- Сервер ничего не удаляет по сети. Ненужные разборы удаляются на самом сервере командой `byteripper-cas gc`.
- Сервер не хранит дампы. Разбор указывает, какой модуль он описывает, но не содержит прошивку, из которой этот модуль взят.
